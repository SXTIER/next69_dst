# Anti-Patterns Verdict

**LLM assessment**: The site no longer has the strongest "AI card grid" smell in the course section. The desktop year page now reads more like a practical curriculum tool. The remaining AI-like tells are structural: repeated bordered cards, English micro-labels (`FILTER`, `YEAR SUMMARY`, `credits`) mixed with Thai student-facing copy, and a predictable hero-plus-cards rhythm on the homepage. These are not fatal, but they make the site feel like a generated product shell rather than a Mahidol/DST-specific student tool.

# Overall Impression

The website is credible and much clearer than a raw curriculum PDF. Desktop is now close to a usable product. Mobile is the weak point: the primary task is "ดูรายวิชา", but the student must pass hero, metrics, overview accordion, filter card, and then course content. The site should become more mobile-task-first.

# What's Working

1. **Desktop course lookup is substantially better**: visible search plus table/list rows make year courses easier to scan than the earlier grid.
2. **Visual system is restrained and readable**: neutral palette, Thai-ready type, strong contrast, and clear focus states support WCAG AA direction.
3. **Curriculum model is trustworthy**: year summary, terms, credits, source PDF, course details modal, prerequisites/corequisites, and optional requirement separation all point to a useful student tool.

# Priority Issues

## [P1] Mobile primary task is buried below too much setup content

**Why it matters**: On a phone, the user reaches actual course cards only after scrolling through hero, metrics, curriculum overview, filter, and section header. Incoming students likely want the course list first, then supporting context. The current order makes mobile feel slower than the data actually is.

**Fix**: On mobile, collapse `ภาพรวมหลักสูตร` by default or move it below courses. Keep a compact sticky/near-top jump row: `รายวิชา`, `แผนรายภาค`, `ตัวเลือก`. The first mobile viewport after the hero should expose search or first course content faster.

**Suggested command**: `$impeccable adapt whole site mobile course flow`

## [P1] Artificial skeleton loading hurts perceived performance

**Why it matters**: Screenshots captured skeleton rows even though the curriculum data is local/static. A student may see a fake loading state on every year navigation, which makes the app feel slower and less stable.

**Fix**: Remove the fixed 220ms `isPreparing` delay for local data, or only show skeleton during real route/data pending states. Prefer immediate render with subtle transition.

**Suggested command**: `$impeccable optimize year page loading states`

## [P2] Homepage has a generic product-shell rhythm

**Why it matters**: The homepage is clean but slightly generic: hero, year cards, summary card. It says what the product does, but not why a DST student should trust it beyond the source document. It misses a stronger first-use orientation.

**Fix**: Add a compact "how to use this" strip tied to student questions: `เลือกปี`, `ดูรายวิชา`, `เปิดรายละเอียด`, `เช็กวิชาที่ต้องเรียนก่อน`. Keep it short and functional, not marketing.

**Suggested command**: `$impeccable onboard homepage first-use orientation`

## [P2] Copy hierarchy mixes product labels and student language

**Why it matters**: Labels like `FILTER`, `YEAR SUMMARY`, `credits`, and mixed English UI labels are understandable, but they make the surface feel tool-generated. Thai-first students should not have to parse system labels that do not add meaning.

**Fix**: Localize functional labels: `ค้นหา`, `ภาพรวมปี`, `หน่วยกิต`, `รายละเอียด`. Keep English only for course titles and source names.

**Suggested command**: `$impeccable clarify whole site labels`

## [P2] Mobile menu is available but not task-oriented

**Why it matters**: Mobile only shows a hamburger at the top-right. The menu likely contains year links, but the most common action after landing is jumping to a year or source document. Hiding all navigation behind the icon increases first-use friction.

**Fix**: Add a small mobile top identity row or quick year selector. Keep hamburger for secondary navigation, but make year switching easier from the year page.

**Suggested command**: `$impeccable adapt mobile navigation`

# Persona Red Flags

**Incoming DST Student**: They can find the year cards and open a year. On mobile year pages, they will likely scroll through overview and filter before the actual course list. This delays the answer to "ปีนี้เรียนอะไรบ้าง?"

**Student Checking Prerequisites**: Course modal is useful, but the path is still list -> row/card -> modal. If prerequisites are the task, there is no visible cue in the list/table that a course has prerequisites. They must open details one by one.

**Keyboard / Assistive Tech User**: Semantic controls exist and focus rings are present. The risk is interaction count: multiple accordions, filter controls, and long card lists can require many tabs. Visible search helps, but mobile overview-first order still creates extra traversal.

# Minor Observations

- The black `N` bubble in screenshots appears to be the Next.js dev indicator, not product UI. Ignore for production, but it visually overlaps mobile screenshots.
- Desktop nav is clean, but active year state is quiet. It is acceptable, but could be stronger for orientation.
- Course table on desktop is clearer than cards, but the rightmost `รายละเอียด ›` repeats on every row. This is okay for affordance, but can be visually reduced after validation.
- Summary cards on mobile are readable, but they consume a full row before the user reaches the plan.
- The site handles reduced motion globally, which is a real accessibility strength.

# Questions to Consider

1. What if the mobile year page made `รายวิชา` the default first section and treated overview as secondary?
2. Does the site need English UI labels at all, outside course names and source titles?
3. Should prerequisites be visible as a small signal in the course table/card, so users do not need to open every modal?
